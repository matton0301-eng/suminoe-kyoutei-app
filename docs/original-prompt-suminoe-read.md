# 実装依頼：住之江 出走表アナライザ「スミノエ・リード」

## 0. このツールの目的

2026年8月9日（日）にボートレース住之江へ現地観戦に行く。
その前夜（8月8日）に、**当日全12レースの出走表を読み込んで、レースごとの判断材料を一枚の表にまとめる**バッチツールを作る。

観戦者は競艇初心者。したがって出力は「数字の羅列」ではなく、
**そのレースを買うべきか見送るべきかを判断できる形**に加工されている必要がある。

### 重要な設計思想

このツールは**勝つための予想ツールではない**。舟券の控除率は約25%あり、
データ分析でそれを覆すことは想定していない。目的は「根拠を持ってレースを見られること」であり、
**精度を装った断定的な出力を絶対に生成しないこと**。具体的には以下を厳守する。

- 存在しない小数精度の「的中確率」を出力しない
- 母数が小さい集計値には、必ず母数（走数）を併記する
- 「推奨買い目」は候補の型を提示するに留め、断定的な推奨文言を使わない

### 納期

2026年8月8日中に実行できること。
**8月7日のうちに、過去日付（例：2026年8月6日）のデータで動作確認を完了させること。**
本番当日に初めて動かす、という状態にしてはならない。

## 1. 実行環境

- Windows 11 / PowerShell 7 ネイティブ（WSLなし）
- Python 3.12
- 仮想環境は `venv` で作成する
- 依存は最小限に。`requests` は使用可。`pandas` は使ってよいが必須ではない
- 出力先ディレクトリ `./output/` を自動生成する

CLIとして以下の形で叩けること。

```powershell
python main.py --date 2026-08-09
python main.py --date 2026-08-09 --format md,csv
python main.py --date 2026-08-06 --dry-run   # 動作確認用
```

`--date` 省略時は翌日を既定値とする。

## 2. データ取得

### 2-1. 一次ソース：公式「番組表ダウンロード」

ボートレース公式サイトが配布している番組表データを使用する。

- 配布インデックス： https://www1.mbrace.or.jp/od2/B/dindex.html
- 形式：LZH圧縮された固定長テキスト
- 内容：全国24場のその日の番組表（＝出走表）

**ファイルURLをハードコードしないこと。** インデックスページを取得してリンクを解決するか、
公開されている命名規則から組み立てたうえで、404時に代替パターンを試すフォールバックを持たせる。

### 2-2. LZHの解凍

Windows環境でLZHを扱う手順を実装する。以下の優先順で試行し、いずれも失敗したら
**明確なエラーメッセージで7-Zipのインストールを案内して終了する**（例外を握りつぶさない）。

1. 7-Zip CLI（`7z.exe`）が PATH または既定インストール先にあれば使用
2. Python の `lhafile` パッケージ
3. いずれも不可なら中断し、手動解凍したtxtを `--local-file` オプションで渡せる導線を用意する

### 2-3. フォールバック：出走表HTML

番組表データが取得できない場合に限り、公式サイトの出走表ページから取得する。

```
https://www.boatrace.jp/owpc/pc/race/racelist?rno={R}&jcd=12&hd=YYYYMMDD
```

- `jcd=12` が住之江
- **リクエスト間隔は最低1.5秒空ける**
- User-Agentを明示し、個人利用の範囲を超える取得は行わない
- 失敗時はリトライ2回まで、指数バックオフ

### 2-4. 文字コード

番組表テキストの文字コードは Shift_JIS 系。`cp932` でデコードし、
失敗時は `errors='replace'` で継続したうえで、該当行を警告ログに出す。

## 3. パース仕様

番組表テキストは固定長フォーマット。住之江（場コード12）の当日分のみを抽出する。

### 3-1. 抽出するレース単位の情報

- レース番号（1〜12）
- レース名／グレード（例：「優勝戦」「予選」）
- 距離
- 電話投票締切予定時刻

### 3-2. 抽出する艇単位の情報（6艇分）

| 項目 | 備考 |
| --- | --- |
| 艇番 | 1〜6 |
| 選手登番 | 4桁 |
| 選手名 | 全角スペース詰めを正規化する |
| 年齢 | |
| 支部 | |
| 体重 | |
| 級別 | A1 / A2 / B1 / B2 |
| 全国勝率 | |
| 全国2連対率 | |
| 当地勝率 | 住之江での勝率 |
| 当地2連対率 | |
| モーター番号 | |
| モーター2連対率 | |
| ボート番号 | |
| ボート2連対率 | |
| 今節成績 | 各日の着順文字列 |

**固定長の桁位置は必ず実データで検証すること。** 選手名に全角スペースが含まれる、
勝率が `0.00` になっている新人がいる等の実例があるため、
サンプル行に対するユニットテストを最低5ケース書くこと。

### 3-3. 欠損の扱い

- 当地勝率が `0.00` の場合、それは「弱い」ではなく**「住之江での出走実績がほぼ無い」**可能性が高い。
  スコアリングで単純に低評価とせず、`当地データなし` として別扱いにする。
- 欠損を0として平均に混ぜないこと。

## 4. 分析ロジック

### 4-1. ベースライン（ハードコード）

ボートレース住之江公式サイト「水面特性・進入コース別情報」より。
集計期間 2026/5/1〜2026/7/31。

コース別1着率（％）:

```
1コース: 56.2   2コース: 15.2   3コース: 13.1
4コース: 10.7   5コース:  3.5   6コース:  1.8
```

1コース決まり手：逃げ 95.8%
枠なり進入率：1枠→1コース 100.0% / 2枠 94.1% / 3枠 91.8% / 4枠 87.2%

**住之江は枠なり進入がほぼ確定しているため、本ツールでは 枠番 = 進入コース として扱う。**

### 4-2. レースごとに算出する4指標

いずれも**3段階の定性評価＋根拠となる数値**をセットで出力する。数値だけ、評価だけ、は不可。

**① イン信頼度（1号艇が逃げ切れそうか）**

判定に使う材料：1号艇の級別、当地勝率、全国勝率、モーター2連対率、今節成績。

- `高`：A1級かつ当地勝率6.00以上、またはモーター2連対率が節内上位
- `中`：上記に届かないが当地勝率5.00以上
- `低`：B級、または当地勝率5.00未満、または当地データなし

**② 波乱リスク（3・4号艇の攻めが利きそうか）**

判定に使う材料：3号艇・4号艇の級別と当地勝率を、1号艇と比較する。

- `高`：3号艇または4号艇の当地勝率が1号艇を上回る、もしくはA1級が3〜6枠にいて1号艇がB級
- `中`：差が0.50以内
- `低`：1号艇が明確に上位

**③ モーター注目艇**

節内全艇のモーター2連対率の中央値を算出し、**中央値+15ポイント以上**の艇を抽出して列挙する。
該当なしの場合は「該当なし」と明示する。

**④ 総合判定**

- `勝負`：イン信頼度が高、かつ波乱リスクが低
- `標準`：上記以外で、極端な不確実性がないもの
- `見送り`：イン信頼度が低、かつ波乱リスクが高（＝読みどころがない混戦）

**判定の根拠を必ず1文で添えること。** 例：「1号艇が当地6.42のA1級、3・4号艇はB1で差が1.2以上あるため。」

### 4-3. 買い目の型（テンプレート提示のみ）

総合判定に応じて、点数上限を守った**買い目の型**を提示する。
具体的な推奨ではなく「この判定ならこういう組み方が定石」という提示に留める。

- `勝負` → 3連単フォーメーション 1着固定 / 2着2艇 / 3着3艇（6点）
- `標準` → 3連単 1着2艇流し（縮小）＋3連複1点
- `見送り` → 買わない、または複勝1点

点数上限は CLI オプション `--max-bets`（既定6）で制御できるようにする。

## 5. 出力

`./output/suminoe_YYYYMMDD.md` と `./output/suminoe_YYYYMMDD.csv` を生成する。

### 5-1. Markdown（人が読む用）

先頭に**サマリー**を置く。ここだけ見れば当日の方針が立つこと。

```markdown
# 住之江 2026/8/9(日) 出走表分析

## サマリー
勝負レース: 3R, 7R, 12R
見送り推奨: 2R, 5R, 9R
モーター注目: 4R-3号艇(2連率58.2%), 12R-1号艇(2連率55.0%)

---

## 12R 優勝戦  締切 20:30
**総合判定：勝負**  イン信頼度=高 / 波乱リスク=低
> 1号艇が当地6.42のA1級。3・4号艇はB1で当地勝率に1.2以上の差があるため。

| 枠 | 選手 | 級別 | 全国勝率 | 当地勝率 | 当地2率 | M2率 | 今節 |
|---|---|---|---|---|---|---|---|
| 1 | ... | A1 | 6.85 | 6.42 | 48.5% | 55.0% | 112 |
...

**買い目の型（6点）**：3連単 1-{2,3}-{2,3,4}
```

住之江の基準値（1コース56.2%等）を、各レース表の下に脚注として1行入れる。

### 5-2. CSV（後で分析する用）

1行1艇（全12レース×6艇＝72行）。ヘッダーあり、UTF-8 BOM付き（Excelで開くため）。
分析指標の列（イン信頼度・波乱リスク・総合判定）も各行に持たせる。

### 5-3. チャット貼り付け用テキスト

`--format chat` を指定すると、**Claudeに貼って相談できる圧縮テキスト**を標準出力に出す。
1レース2〜3行、全12レースで100行以内に収まるよう情報を絞る。

## 6. ログとエラー処理

- 取得・解凍・パース・分析の各段階で進捗を標準出力に表示する
- パースできなかったレースがあっても**全体を止めない**。該当レースを「取得失敗」として出力に残し、
  末尾に警告サマリーをまとめる
- 取得した生テキストは `./cache/` に保存し、再実行時はキャッシュを使う
  （`--no-cache` で無効化）。**同じデータを何度も取りに行かないこと。**

## 8. 進め方

実装に入る前に、以下2点を提示して確認を取ること。

1. 番組表データの実物を1件取得し、**固定長の桁位置がどう解釈できるか**の分析結果
2. 分析ロジック4指標のしきい値が妥当か（実データで数レース試算した結果）

桁位置の解釈を推測のまま実装すると全部ずれるため、ここは必ず実データで確認してから進めること。

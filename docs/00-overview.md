## 1. 何を作るか

2026-08-09（日）、ボートレース住之江のナイター開催（**優勝戦日**）を VIP 席で初観戦する。
そのための**2つのツール**を作る。

| ツール | 種類 | 使う場面 | 仕様書 |
|---|---|---|---|
| **スミノエ・リード** | Python CLI（ローカル実行） | **当日朝**: 全12Rの出走表を分析し、レースごとの判断材料を1枚のmdにまとめる | [02-suminoe-read-spec.md](02-suminoe-read-spec.md) |
| **スミノエ・ログ** | Next.js PWA（Vercel・オフライン動作） | **当日現地**: Android片手操作で1レース20秒以内の観察記録を取る＋賭式別の買い目を見る | [01-suminoe-log-spec.md](01-suminoe-log-spec.md) |

**2ツールは JSON 1本で緩くつながる。**

```
[PC] スミノエ・リード  ──→  output/suminoe_20260809.json
                                    │ 中身をコピーして貼り付け（通信しない）
                                    ▼
[スマホ] スミノエ・ログ「買い目」タブ ──→ 賭式別の買い目
                                    ▲
                   当日の記録（コース別1着率の実測）で補正
```

- リードは出走表の評価値と判定を JSON で出す。**買い目の組み立てはログ側**で行う
  （当日の実測でコース別1着率を補正するため、アプリ側にロジックを置く）
- 取り込みは貼り付け方式。**アプリから外部通信は一切しない**のでオフライン要件を崩さない
- md はスマホの任意のアプリで読んでもよい（詳しい根拠や出走表を読みたいとき）

> 当初は「2ツールを結合しない」方針だったが、2026-08-07 のユーザー要望
> （「データをもとに買い方の買い目も画面上で教えてほしい」）により買い目タブを追加した。
> 経緯は仕様 01 §0-R9 / R10。

## 2. 設計思想（両ツール共通）

- 勝つための予想ツールではない（舟券の控除率約25%を覆す想定はしない）。**根拠を持ってレースを見る**ための道具
- 精度を装った断定を出さない。母数の小さい集計には母数を併記する
- 「確実に当日動くこと」＞作り込み

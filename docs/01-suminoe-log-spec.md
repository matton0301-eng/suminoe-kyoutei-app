## 0. 元仕様からの改訂点サマリー

| # | 改訂 | 理由 |
|---|---|---|
| R1 | **Service Worker を必須要件に昇格**。静的エクスポート（`output: 'export'`）+ 手書きSW | manifest + アイコンだけでは「初回読み込み後オフラインで全機能」は保証されない。競艇場の回線不安定が最大リスクであり、SWなしのPWAは要件未達 |
| R2 | **起動時の下書き復元を明文化** | 元仕様は `suminoe-draft` への退避のみ記述。ブラウザ強制終了→再起動で入力途中を失わないよう、復元まで仕様化 |
| R3 | **直前の記録カードに的中○×を表示** | predictedFirst と resultFirst の比較は保存時に確定する。1タップも増やさず現地の楽しさが増える |
| R4 | **クリップボード失敗時のフォールバック** | Android の一部環境で `navigator.clipboard` が失敗し得る。全文選択済み textarea を出す |
| R5 | **レース番号は12で停止**（13にしない・1へ巻き戻さない） | 12R保存後の自動+1で13Rが生まれる穴を塞ぐ |
| R6 | **`schemaVersion` フィールド追加** | localStorage データの後方互換の保険。コスト数行 |
| R7 | **PWAアイコンの仕様具体化**（192/512px maskable） | 「アイコン」とだけ書かれていた部分の実装可能化 |
| R8 | **QAチェックリスト追加**（§8） | 「確実に当日動くこと」最優先の元方針を検証手順に落とした |
| R9 | ~~スミノエ・リードとのデータ連携は行わない~~ → **R10 で撤回** | — |
| R10 | **買い目タブを追加**（v1.1 で追加。ユーザー要望による仕様変更） | 「3連単や3連複などさまざまな買い方があるので、データをもとに買い目も画面上で教えてほしい」との要望。リードのJSON出力を貼り付けて取り込み、賭式ごとの買い目を表示する。詳細は §3 タブ2 |
| R11 | **デザイン刷新（§4）**。near-black から水面の藍へ、署名要素に鏡面反射 | 「チープ」との指摘。元仕様のトークンがAI量産パターンに一致していた |
| R13 | **収支タブを追加（§3 タブ4）**。当選率と1点100円での収支 | 「結果と照らし合わせて当選率を発表するタブ」「最低金額をかけていくら返ってきたか」との要望 |
| R14 | **展示の反映・締切の自動選択・レース連動・結果欄の折りたたみ** | 現地の操作を減らすため。展示は現地でしか得られない直前情報で、事前分析に対する固有の価値になる |
| R15 | **light テーマを既定にし、dark（ナイター用）へ切替可能に** | 「背景が暗いのが嫌」との要望。ただし元仕様の「夜間にまぶしくならない」要件は残るため、切替で両立させた |
| R16 | **波しぶきと艇のシルエットを画面下部に固定** | 「競艇といえば波しぶき」「ターンで飛び散る様子をシルエットで」との要望 |
| R17 | **日付のハードコードを撤去**。扱う日は出走表の日付で決まる | 8/9固定だったため、8/7のデータを表示しているのに 8/9 と出ていた。特定の1日の専用アプリにしない |
| R12 | **出走表をアプリに同梱**（`public/racecard.json` を起動時に自動読み込み） | 31KBのJSONをスマホで貼り付けるのは手間。当日朝の自動更新と組み合わせ、アプリを開くだけで反映されるようにした |

決まり手は元仕様どおり**5種のまま**とする（公式には「恵まれ」等もあるが住之江1コースで0.3%。初心者の判断負荷を優先し、判断できない場合は未選択=nullでよい）。

## 1. 技術スタック（確定）

- Next.js 16（App Router）+ TypeScript + Tailwind CSS
- `output: 'export'` による**静的エクスポート**。API ルート・サーバー機能は使わない
- 状態管理: `useState` / `useReducer` のみ
- 永続化: `localStorage` のみ（Firebase・認証・外部API 一切なし)
- **Service Worker はビルド時に生成**（`scripts/build-sw.mjs` が `out/` を走査して `out/sw.js` を出力）:
  install で全アセットをプリキャッシュ、fetch は cache-first。next-pwa 等のライブラリは**入れない**（納期リスク・依存最小化）。
  Next.js はアセット名にハッシュを付けるため、プリキャッシュ一覧の手書きは必ずズレる。ビルド出力から生成する
- PWA: `manifest.json` + アイコン（192px / 512px、`purpose: "any"` と `"maskable"` の両方を登録）。
  アイコンは `scripts/make-icons.mjs` が Node 組み込みの zlib だけで PNG を生成する（依存ゼロ）
- Vercel にデプロイ、単一URL運用
- 外部フォント禁止。システムフォントスタック（`system-ui, -apple-system, "Segoe UI", "Noto Sans JP", sans-serif`）
- `'use client'` の単一ページ構成。ルーティングなし

### オフライン要件（最重要）

1. 初回アクセス（自宅Wi-Fi等）でSWが全アセットをキャッシュする
2. 以降、**機内モードでも起動・全機能が動作**すること
3. SW 更新は起動時に確認し、新しい版が主導権を取ったら**1回だけ自動リロード**する。
   キャッシュ優先のままだと修正をデプロイしても端末が古い版を表示し続けるため（8/8に修正を入れる可能性がある）。
   入力途中は下書きに即時保存しているのでリロードで失われない

## 3. 画面構成

下部固定タブ5面: `[記録] [買い目] [集計] [収支] [書出]`。ヘッダーは「スミノエ・ログ 8/9(日)」をコンパクトに。

### タブ1: 記録（デフォルト）

上から順に:

1. **レース番号**: `1R` を大きく表示、左右に `−`/`＋`。範囲1〜12。保存で自動+1、**ただし12で停止**（R5）
2. **予想「1着になると思う艇」**: 枠色ボタン6個×1列。1タップ選択。選択中は白枠線+拡大。実質必須（ただし保存自体は妨げない）
3. **「展示で速そうに見えた艇（任意）」**: 同ボタン。再タップで解除可
4. **結果 1着/2着/3着**: 3行×枠色ボタン6個。**同一艇を別の行で選んだら元の行から自動で外す**
5. **決まり手「1着はどう決まった？」**: 5ボタン2行、各ボタンに補足文言（`逃げ — 1号艇が先頭のまま` 等。**補足は削らない**）
6. **水面メモ**: `静か`/`ふつう`/`荒れてる` 3択（補足「2マークで艇が暴れてたか」）+ 1行テキスト（placeholder「気づいたこと」）
7. **保存ボタン**: 幅いっぱい・高さ56px以上・固定表示。文言「このレースを記録する」。保存後トースト「◯R を記録しました」→フォームリセット→レース番号+1。**未入力でも保存可**。結果1着が未入力のときのみ確認ダイアログ
8. **直前の記録カード**: 直近1件を表示、**予想的中なら○・外れなら×を表示**（R3）。タップで編集モードへ

**下書き（R2）**: フォームの全入力は変更のたびに `suminoe-draft` へ即時保存。起動時に draft が存在すれば復元する。保存成功時に draft をクリア。

### タブ2: 買い目（v1.1 で追加・R10）

スミノエ・リードが出力した JSON を取り込み、レースごとに**賭式別の買い目**を表示する。

**設計思想（リードと共通・厳守）**: 控除率約25%を覆す想定はしない。出すのは
「その賭式で買うならこういう組み方が定石」という**型の提示**であり、推奨ではない。
金額は扱わない。存在しない精度の的中確率も出さない。控除率の注意を画面から消さない。

**① データ取り込み**
- リードの `output/suminoe_YYYYMMDD.json` を貼り付けて取り込む（オフライン維持のため通信しない）
- `suminoe-racecard-20260809` キーに保存。記録とは別キーにして「全記録を消す」で消えないようにする
- 境界で厳密に検証し、`schemaVersion` 不一致・壊れたJSON・レース0件は理由付きで拒否する

**② レース選択**
- 12レースをボタンで選択。各ボタンに判定（勝負／標準／見送）を併記し、当日の全体像が一覧できる
- 判定の件数集計を下に表示

**③ レース情報**
- 総合判定・イン信頼度・波乱リスク・判定根拠・モーター注目・注記（当地データなし等）
- 出走表（枠／選手／級別／当地勝率／全国勝率／M2率）。軸に印を付ける

**④ 買い目の組み立て方**
- 軸と相手の評価順を明示する
- **当日の実測でコース別1着率を補正する**（縮小推定）。記録が3件未満なら基準値のみ。
  重み = min(0.5, 結果件数 / 24)。母数が小さいうちに実測へ振り切らない
- 軸が1号艇でない場合は「1コース1着率56.2%なので1号艇を切る判断は慎重に」と注意を出す

**⑤ 賭式ごとの買い目（8種）**

| 賭式 | 組み方 | 点数 |
|---|---|---|
| 3連単フォーメーション | 軸-{相手上位2}-{相手上位4} | 6点 |
| 3連単ボックス | 軸＋相手上位2 の3艇ボックス | 6点 |
| 3連複 | 軸固定＋相手上位3から2艇 | 3点 |
| 2連単 | 軸-{相手上位2} | 2点 |
| 2連複 | 軸={相手上位2} | 2点 |
| ワイド（拡連複） | 軸={相手上位2} | 2点 |
| 単勝 | 軸 | 1点 |
| 複勝 | 軸 | 1点 |

- 各賭式に**何が当たれば的中か**の説明を添える（初心者が賭式を理解できるように）
- 判定ごとに定石の賭式へ印を付けて先頭に並べる（勝負→3連単F / 標準→3連複・2連単 / 見送り→複勝・ワイド）
- 3連単の3着候補に2着候補を含める。含めないと「2着2号艇→3着3号艇」が買えず不自然になる。
  リード側の型提示と同じ組み方に揃える

**⑥ 見送りレースの扱い**
- 「このレースは見送りが基本」「買わずに見るのも十分な選択」を買い目より前に表示する
- そのうえで「それでも買うなら」という前提で型を出す

**⑦ 免責**
- 控除率25%の注意を常時表示。「これは推奨ではありません」を明記

### タブ3: 集計

1. **予想的中率**: `1着予想の的中 3 / 7 レース（42.9%）`（予想・結果とも入っているレースのみ母数に含める）
2. **コース別1着率（当日 vs 基準）**: 横棒グラフ+数値。基準値は破線マーカー。**差が±10pt以上は差分数値を強調**
3. **決まり手内訳**: 件数と割合
4. **今日の水面の読み**（自動生成1文）:
   - 1C1着率が基準+10pt以上 →「イン特強。1号艇の信頼度が高い日。」
   - 基準−10pt以下 →「インが崩れてる。3・4号艇の攻めが利く日。」
   - 「荒れてる」が記録数の過半 →「2マークが荒れてる。逆転に注意。」
   - その他 →「おおむね基準どおり。セオリー重視で。」
   - **3レース未満は判定を出さず**「あと◯レース記録すると傾向が出ます」
5. 記録0件時:「まだ記録がありません。記録タブから1レース目を入れてください。」

### タブ4: 収支（v1.3 で追加・R13）

レース終了後に、提示した買い目がどうだったかを**1日通算**で出す。
レース単位の照合は買い目タブ（タブ2）にあり、こちらは全レースの合計。

**① 全体**
- 回収率（払戻÷投資）を最大の数字として出す
- 投資額・払戻額・収支、確定レース数、1号艇1着率
- 「1レースあたり◯円（8賭式の合計n点）を◯レース買った前提」を明記する

**② 賭式ごとの当選率**（回収率の高い順）
- 当選レース数/母数、当選率、投資、払戻、回収率
- 最高配当の1点（レース番号・組み合わせ・金額）

**③ 判定ごとの結果**
- 勝負／標準／見送り ごとに レース数・1号艇1着数・軸が1着の数・収支

**④ レースごと**
- 着順・決まり手・収支・的中した賭式名

**⑤ 免責（必須）**
- 「控除率は約25%あるので、続ければ回収率は75%前後に近づく」
- 「100%を超えていても1日ぶんのばらつきで、分析が優れている証拠ではない」
- 「数字を見て買い方を大きく変えないでください」

**金額の扱い**: 1点100円（競艇の最低購入単位）で固定。金額の入力機能は持たない。
2026-08-06 の実データで、合計が賭式ごと・レースごとの積み上げと一致することを
テストで固定している（金額を扱うため厳密に検算する）。

### タブ5: 書き出し

1. **テキスト書き出し**: 整形テキスト（元仕様のフォーマット例に従う）をプレビュー表示+コピー
2. **CSV書き出し**: ヘッダー行あり
3. コピーは `navigator.clipboard.writeText()`。**失敗時は全文選択済みの textarea を表示して手動コピーに誘導**（R4）
4. **全記録削除**: 確認ダイアログ必須。ボタンは小さく目立たない配置

## 4. デザイン方針（v1.2 で刷新・R11）

### 刷新の理由

元仕様のトークン（背景 #0E1519 + アクセント #C15F3C）で実装したところ、
利用者から「チープ」との指摘を受けた。原因は3つ。

1. near-black 背景 + くすんだ単色アクセントは、**AIが量産する典型パターン**そのものだった
2. 全セクションが同じ角丸カードの羅列で、情報の階層がなかった
3. 装飾を削りすぎ、「抑制」ではなく「未完成」に見えていた

### 方向: 「静水面（Still Water）」

住之江はプール型の静水面で「静水面の聖地」と呼ばれ、鏡のような水面にナイター照明が映り込む。
**他の競艇場では成立しない特徴**なので、これを配色と署名要素の軸に据える。

```
--color-bg-deep:    #06111C   夜の水面（水底）
--color-bg-panel:   #0B1A2A   パネル（水面下）
--color-bg-raised:  #14293D   持ち上げた面
--color-text-main:  #E9F2F7   水しぶきの白
--color-text-mute:  #7A96A8   沈んだ補助色
--color-accent:     #FFB84D   ナトリウム灯（ナイター照明）
--color-accent-hot: #FFE4A8   照明の芯
--color-line:       #1F3A52   罫線
```

背景は単色ではなく、上が浅く下が深い縦グラデーションで水面の深度を表す。

### 署名要素: 鏡面反射

レース番号（画面で最大の要素、68px・極太）の直下に、**反転した像を薄く（opacity 0.16）**置き、
下に向かってフェードさせる。静水面に映り込む像。`globals.css` の `.mirror`。

### 色の役割分担（重要）

accent の黄橙は5号艇の黄と近い。混同を防ぐため役割を分ける。

- **艇色6色 = 面**（枠色ボタンの正方形）
- **accent = 線・文字・光彩**（選択時の光彩 `.lamp-glow`、強調数値、主要ボタン）

accent 背景に乗る文字は `--color-bg-deep`（暗い藍）。白文字は読めない。

### その他

- **彩度の高い色は枠番6色 + accent だけ**。他は徹底して抑える
- 見出しは小さく（13px）字間を広げ、巨大な数値とのコントラストを作る
- 見出しの左に縦罫（`.rule-start`）。装飾ではなく階層を示す
- 数値は `tabular-nums`
- **枠色ボタンは幅360pxで48px角以上、間隔8px以上を保つ**（§6の計算参照）
- モーションは選択スケール・光彩・トーストのみ。`prefers-reduced-motion` 尊重
- フォーカスリングを消さない（accent色）

## 5. データ構造

```ts
type Boat = 1 | 2 | 3 | 4 | 5 | 6;
type Kimarite = '逃げ' | 'まくり' | '差し' | 'まくり差し' | '抜き';
type Suimen = '静か' | 'ふつう' | '荒れてる';

interface RaceLog {
  id: string;            // crypto.randomUUID()
  raceNo: number;        // 1-12
  predictedFirst: Boat | null;
  tenjiFast: Boat | null;
  resultFirst: Boat | null;
  resultSecond: Boat | null;
  resultThird: Boat | null;
  kimarite: Kimarite | null;
  suimen: Suimen | null;
  memo: string;
  savedAt: string;       // ISO8601（表示はJST）
}

interface StoredData {
  schemaVersion: 1;      // R6
  logs: RaceLog[];
}
```

- 本体キー: `suminoe-log-20260809` / 下書きキー: `suminoe-draft` / 出走表キー: `suminoe-racecard-20260809`
- 出走表は記録と**別キー**にする。「全記録を消す」で出走表まで消えないようにするため
- 保存は**デバウンスなし即時**
- localStorage 不可の環境ではクラッシュせず警告バナーを出して動作継続（メモリ上のみ）

## 6. 品質要件

- 第一ターゲット: Android Chrome、画面幅360〜430px
- **横スクロールを発生させない。** 枠色ボタン6個の幅計算が最も厳しい:
  ```
  360 − main の左右余白12 − セクションの左右余白16 = 332px
  332 = 6ボタン × 48.67 + 5隙間 × 8
  ```
  実測で幅360pxのとき 48.33px角・隙間8.0px・横スクロールなしを確認済み。
  この余白を増やすと48pxを割るため、`main` の `px-1.5` と セクションの `px-2` は動かさないこと
- `npm run build`（静的エクスポート）がエラーなく完了

# 買い目パターンとオッズ期待値 設計

> 2026-08-09 作成。当日（優勝戦日）に使うための機能強化。
> 依頼は2つ: (1) レースごとに「堅実／勝負／穴」の買い方を出す (2) 回収率を意識した精度向上。

## この機能が守る前提

**回収率100%超は保証しない。約束もしない。** 控除率25%は「平均払戻75%」を意味する。
これを超えるには自分の見立てが市場（オッズ）より正確で、その優位性が25%を上回る必要がある。
ここで作るのは「モデルの見立てとオッズを比べ、割に合う買い目を拾う」仕組みまで。

したがって次を必ず守る。

- **期待値が1.0未満なら、そのまま低いと表示する。** 数字を作って100%超に見せない
- **確率は較正（calibration）を通したものだけ出す。** 予測1着確率と実際の1着率のズレを
  過去データで測り、その母数と誤差を画面に添える
- 較正が取れていない項目（3連単の順序など）は「参考」と明示する
- 金額は扱わない（既存方針の維持）

既存の設計思想（`CLAUDE.md`「設計思想」）のうち「存在しない精度の的中確率を出さない」は
**「検証していない確率を出さない」の意味に更新する**。検証した確率は、母数と誤差付きで出す。

## 全体の流れ

## 1. 確率モデル（`lib/probability.ts`）

既存 `lib/betting.ts` の `firstScore` / `placeScore` を確率に変換する。**別実装を持たない**
（スコアの計算は betting.ts のものをそのまま使う）。

- **1着確率**: ソフトマックス `p_i = exp(s_i / T) / Σ exp(s_j / T)`。
  温度 `T` は較正で決める（小さいほど1位に確率が集中する）
- **2着以降**: Harville。1着が決まったら、その艇を除いて `placeScore` で再正規化する
- 出力: 各艇の1着確率、3連単120通りの確率、3連複20通りの確率

Harville は「1着になった艇の強さが2着争いに影響しない」と仮定する近似で、
実際には人気馬（艇）の2着確率を過大に見積もる傾向が知られている。
**この偏りは較正で測り、結果を画面に出す。** 補正係数は入れない（検証していない補正を足さない）。

## 2. 較正の検証（`scripts/calibrate.ts` → `public/calibration.json`）

材料は過去の開催日（`cache/history/` に63日分ある）。各日について番組表を取得し、
アプリと同じ形式（`racecard.json`）に変換して `cache/cards/` に置く（`collect-cards.py`）。

検証すること:

1. **1着確率の較正**: 予測確率を10%刻みのビンに分け、各ビンの予測平均と実際の1着率を比べる
2. **温度 T の決定**: 対数損失（log loss）が最小になる T を探す
3. **3連単の的中率**: モデル上位N点の的中率（順序の当たり具合）

出力 `public/calibration.json`:

```json
{
  "schemaVersion": 1,
  "generatedAt": "2026-08-09T09:00:00+09:00",
  "days": 63, "races": 750,
  "temperature": 1.0,
  "logLoss": 1.42,
  "bins": [{ "predicted": 0.55, "actual": 0.52, "n": 210 }],
  "topNHitRate": [{ "n": 6, "rate": 0.31 }]
}
```

アプリはこれを読み、期待値の注記に「予測55% → 実際52%（210レース）」のように添える。

**リークを避ける。** 番組表の値だけで検証し、過去成績の実測を混ぜる `enrich` は通さない
（enrich は当日より後のデータも含むため、過去日に当てると未来を見たことになる）。

## 3. オッズの取り込み（`tools/suminoe-mcp/scripts/fetch-odds.ts`）

既存の `lib/odds.ts`（3連単・検証済み）を再利用し、**3連複パーサを追加**する。
公式ページ: `odds3t`（120通り）と `odds3f`（20通り）。

- 12R分を1.5秒間隔で取得 → `apps/suminoe-log/public/odds.json`
- **取得時刻（fetchedAt）をレースごとに持つ。** オッズは締切直前に動くので、
  画面には必ず「何時何分時点」を出す
- 発売前（オッズ未公開）のレースは `null` で残す。直前情報と同じ「まだ」の扱い
- 冪等: 前回と全レースのオッズが同じならデプロイしない
- 直前情報と同じ30分サイクルのタスクに相乗りする（`tenji-and-deploy.sh` から呼ぶ）

## 4. 買い目パターン（`lib/patterns.ts`）

3本を出す。各パターンは既存の `BetSuggestion` の軸・相手評価をそのまま使う。

| パターン | 賭式 | 選び方 | 点数の目安 |
|---|---|---|---|
| 堅実 | 3連複 | モデル確率の高い順に積む | 3〜4点 |
| 勝負 | 3連単 | 期待値の高い順（軸は固定） | 6点前後 |
| 穴 | 3連単 | 期待値1.0以上かつオッズ50倍以上 | 2〜4点 |

各パターンが持つ値:

- `tickets` 買い目
- `hitProbability` モデル上の的中率（合計確率）
- `oddsRange` 最小〜最大オッズ、`expectedValue` 期待値（Σ p_i × odds_i / 点数）
- `note` 期待値が1.0未満なら「割に合わない」と明示する文言

**穴は該当が無ければ「該当なし」を出す。** 無理に候補を作らない。
オッズが取れていないレースでは期待値を出さず、確率だけを出す（型の提示に戻る）。

## 5. 画面（`components/BetsTab.tsx`）

出走表の下に3カードを横並び（幅360pxでは縦積み）。各カードに賭式・点数・買い目・
的中率・期待値。期待値には較正の注記を必ず添える。

既存の8賭式一覧はその下に残す（型の比較として引き続き使える）。

見送り判定のレースは、既存の「買わないのも十分な選択」を3カードより上に置く。

- `lib/odds.test.ts`（MCP側）3連複パーサを実ページの fixture で検証

## やらないこと

- 賭け金の配分・資金管理（金額は扱わない方針の維持）
- Harville の補正係数（検証していない補正を入れない）
- 締切直前のオッズ自動追随（30分サイクルの範囲に留める。取得時刻を出して判断は人に委ねる）

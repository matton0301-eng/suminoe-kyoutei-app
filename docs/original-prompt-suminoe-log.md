# 実装依頼：住之江観戦記録アプリ「スミノエ・ログ」

## 0. このプロジェクトの前提

2026年8月9日（日）にボートレース住之江へ初めて現地観戦に行く。
VIP席から観覧しながら、**Android端末を片手で操作して**レースの観察記録を取りたい。

競艇初心者のため、「数字を打ち込む」「専門用語を選ぶ」といった操作は極力排除する。
**タップだけで1レース分の記録が20秒以内に終わること**が最優先要件。

納期は2026年8月8日中。作り込みよりも「確実に当日動くこと」を優先する。

---

## 1. 技術スタック

- Next.js 16（App Router）+ TypeScript
- Tailwind CSS
- 状態管理はReactの`useState` / `useReducer`のみ（Zustand等は不要）
- 永続化は`localStorage`のみ（**Firebase・認証・APIルートは一切使わない**）
- Vercelにデプロイして単一URLで運用
- PWA対応（`manifest.json` + アイコン）してAndroidのホーム画面に追加可能にする

### 重要な制約

- **オフラインで完全動作すること。** 競艇場は来場者が多く回線が不安定になりやすい。初回読み込み後はネット接続なしで全機能が使えること。
- ページは`'use client'`の単一ページ構成でよい。ルーティングは不要。
- 外部フォントの読み込みはオフライン動作を阻害するため使わない。システムフォントスタックで組む。

## 2. ドメイン知識（実装に必要な前提）

### 枠番と艇色の対応

競艇は枠番ごとに艇の色が world-wide で固定されている。**この色をUIの基本言語として使う。**

| 枠番 | 色   | 背景色      | 文字色      |
| -- | --- | -------- | -------- |
| 1号艇 | 白   | #FFFFFF  | #1A1A1A  |
| 2号艇 | 黒   | #2B2B2B  | #FFFFFF  |
| 3号艇 | 赤   | #D83A34  | #FFFFFF  |
| 4号艇 | 青   | #2A6FC9  | #FFFFFF  |
| 5号艇 | 黄   | #F2C230  | #1A1A1A  |
| 6号艇 | 緑   | #3F9A54  | #FFFFFF  |

### 決まり手（1着の決まり方）5種

`逃げ` / `まくり` / `差し` / `まくり差し` / `抜き`

### 住之江の基準データ（ハードコードして比較表示に使う）

出典：ボートレース住之江公式サイト「水面特性・進入コース別情報」
集計期間 2026/5/1〜2026/7/31

コース別1着率（％）:

```
1コース: 56.2
2コース: 15.2
3コース: 13.1
4コース: 10.7
5コース:  3.5
6コース:  1.8
```

1コースの決まり手内訳（％）: 逃げ 95.8 / 抜き 3.8 / 恵まれ 0.3

**住之江は進入がほぼ枠なり**（1枠が1コースになる率100.0%、2枠→2コース94.1%、3枠→3コース91.8%）。
したがって本アプリでは **枠番 = 進入コース** として扱ってよい。コース入力は設けない。

## 3. 画面構成

単一ページ内をタブで3面に分ける。タブは画面**下部**に固定（片手操作のため）。

```
┌─────────────────────────┐
│  スミノエ・ログ    8/9(日)   │  ← ヘッダー（コンパクトに）
├─────────────────────────┤
│                         │
│                         │
│      各タブのコンテンツ       │
│                         │
│                         │
├─────────────────────────┤
│  [記録]  [集計]  [書き出し]   │  ← 下部固定タブ
└─────────────────────────┘
```

### タブ1：記録（デフォルト表示）

現在のレースを1件入力する画面。上から下へ流れるように配置する。

**① レース番号**
- 大きく`1R`のように表示。左右に`−` `＋`ボタン。
- 保存するたびに自動で+1される。手動修正も可能。
- 1〜12の範囲。

**② 予想（買わなくても必ず入力させる）**

> 見出し文言：「1着になると思う艇」

- 枠色ボタン6個を横1列。1タップで選択。選択中は白い枠線＋少し拡大。
- **必須項目はこの1つだけ。** 2着以下の予想は入力させない（初心者には負担が重く、レース前は時間がない）。

**③ 展示で速そうな艇**（任意）

> 見出し文言：「展示で速そうに見えた艇（任意）」

- 同じく枠色ボタン6個。未選択のままでも保存できる。
- 「選ばない」を選べるよう、もう一度押すと選択解除できること。

**④ 結果 1着・2着・3着**

> 見出し文言：「結果」／その下に「1着」「2着」「3着」の3行

- 各行に枠色ボタン6個。合計3タップ。
- **同じ艇を重複選択したら、その艇は他の行から自動的に外す**（誤入力防止）。

**⑤ 決まり手**

> 見出し文言：「1着はどう決まった？」

- 5つのボタンを2行で配置。各ボタンには短い補足を添える。
  - `逃げ` — 1号艇が先頭のまま
  - `まくり` — 外から抜き去った
  - `差し` — 内側を突いた
  - `まくり差し` — 外から回って内へ
  - `抜き` — 直線で追い抜いた
- 補足文言があることで初心者が判断できる。これは削らないこと。

**⑥ 水面のメモ**（任意）

- `静か` / `ふつう` / `荒れてる` の3択ボタン。
  補足として「2マークで艇が暴れてたか」と添える。
- 自由記述のテキストエリアを1つ（1行、プレースホルダは「気づいたこと」）。

**⑦ 保存ボタン**

- 画面下部に大きく固定表示。文言は「このレースを記録する」。
- 押下後はトーストで「◯R を記録しました」と表示し、フォームをリセットしてレース番号を+1する。
- **未入力でも保存できてよい**（現地では取りこぼしが起きる。入力を強制しない）。
  ただし結果1着が未入力の場合のみ、確認ダイアログを出す。

**⑧ 直前の記録**

- 保存済みの直近1件をカード表示。タップで編集モードに戻れる。

---

### タブ2：集計

当日の傾向を、**住之江の基準値と並べて**表示する。これがこのアプリの中核価値。

**① 予想の的中率**

```
1着予想の的中   3 / 7 レース （42.9%）
```

**② コース別1着率（当日 vs 基準）**

各コースを横棒グラフで表示。当日の値を実線バー、基準値を破線のマーカーで重ねる。
数値も併記する。

```
1コース  ████████████░░░  62.5%  （基準 56.2%）  +6.3
2コース  ███░░░░░░░░░░░░  12.5%  （基準 15.2%）  −2.7
...
```

基準との差が **+10ポイント以上／−10ポイント以下** の項目は、差分の数値を強調表示する。

**③ 決まり手の内訳**

当日の決まり手を件数と割合で一覧表示。

**④ 今日の水面の読み**

集計結果から短い一文を自動生成して表示する。判定ロジックは以下。

- 1コース1着率が基準+10pt以上 → 「イン特強。1号艇の信頼度が高い日。」
- 1コース1着率が基準−10pt以下 → 「インが崩れてる。3・4号艇の攻めが利く日。」
- 「荒れてる」の水面メモが記録数の半分以上 → 「2マークが荒れてる。逆転に注意。」
- いずれにも当てはまらない → 「おおむね基準どおり。セオリー重視で。」

記録が3レース未満のときは、判定を出さずに「あと◯レース記録すると傾向が出ます」と表示する。
**サンプル数が少ない段階で断定的な判定を出さないこと。**

---

### タブ3：書き出し

**① テキストで書き出す**

全記録を人間が読める整形テキストに変換し、`navigator.clipboard.writeText()`でコピー。
プレビューも画面に表示する。フォーマット例：

```
■ 住之江 2026/8/9 観戦ログ

1R  予想:1号艇 → 結果:1-3-2  決まり手:逃げ  水面:ふつう
    展示速い:4号艇
2R  予想:1号艇 → 結果:4-1-5  決まり手:まくり  水面:荒れてる
    展示速い:4号艇 / メモ:1号艇のターンが流れてた
...

【集計】
予想的中 3/7 (42.9%)
1コース1着率 62.5%（基準56.2%）
決まり手 逃げ4 / まくり2 / 差し1
```

**② CSVで書き出す**

同じデータをCSV形式でコピー。ヘッダー行あり。

**③ 全記録を消す**

確認ダイアログを挟んでlocalStorageをクリア。誤操作防止のため、ボタンは他より小さく目立たない配置にする。

## 4. デザイン方針

### コンセプト

**ナイター開催の屋外・薄暗い観客席で、視認性を確保しつつ艇色が正しく見えること。**

背景は濃紺〜黒に寄せたダークUIとする。理由は3つ。夜間の屋外で画面がまぶしくならないこと、艇色（特に白と黄）がコントラストよく際立つこと、そして水面のナイター照明という題材に素直であること。

一般的なダークUIの「黒＋アクセント1色」に流れず、**背景は水面を想起させる深い青緑寄りのダークトーン**にする。

### カラートークン

```
--bg-deep:    #0E1519   ページ背景（深い水面）
--bg-panel:   #18242A   カード・パネル
--bg-raised:  #223338   選択可能要素の面
--text-main:  #E8EDEE   主要テキスト
--text-mute:  #7E9198   補足テキスト
--accent:     #C15F3C   アクセント（保存ボタン、強調数値）
--line:       #2E434A   罫線
```

枠番6色は前掲の表のとおり。**この6色だけが彩度の高い色**であり、それ以外のUIは徹底して抑える。艇色が主役であることを守ること。

### タイポグラフィ

- 枠番の数字：極太・大きく。ボタン内で最も強い要素。
- 数値（％・件数）：等幅数字（`font-variant-numeric: tabular-nums`）で桁を揃える。集計画面のバーグラフと数値が揺れないようにする。
- 見出し：太めのサンセリフ、サイズは控えめ。装飾しない。
- フォントファミリはシステムフォントスタック（`system-ui, -apple-system, "Segoe UI", "Noto Sans JP", sans-serif`）。

### タッチターゲット

- 枠色ボタンは **最小48×48px**、できれば56px角。片手の親指で押せること。
- ボタン間の間隔は8px以上。誤タップを防ぐ。
- 保存ボタンは横幅いっぱい、高さ56px以上。

### モーション

- 選択時のスケール変化とトースト表示のみ。それ以外のアニメーションは入れない。
- `prefers-reduced-motion`を尊重する。

## 5. データ構造

```ts
type Boat = 1 | 2 | 3 | 4 | 5 | 6;
type Kimarite = '逃げ' | 'まくり' | '差し' | 'まくり差し' | '抜き';
type Suimen = '静か' | 'ふつう' | '荒れてる';

interface RaceLog {
  id: string;            // crypto.randomUUID()
  raceNo: number;        // 1-12
  predictedFirst: Boat | null;
  tenjiFast: Boat | null;
  resultFirst: Boat | null;
  resultSecond: Boat | null;
  resultThird: Boat | null;
  kimarite: Kimarite | null;
  suimen: Suimen | null;
  memo: string;
  savedAt: string;       // ISO8601
}
```

localStorageキーは `suminoe-log-20260809`。
**保存はデバウンスせず即時**に行う。現地での取りこぼしを防ぐため、フォーム入力のたびに下書きも別キー（`suminoe-draft`）へ退避すること。

## 6. 品質要件

- Android Chrome（画面幅360〜430px）を第一ターゲットとして検証する。
- キーボード操作でのフォーカスリングを消さない。
- localStorageが使えない環境でもクラッシュせず、警告を表示して動作は継続する。
- 記録0件のときの集計タブは、空の状態として「まだ記録がありません。記録タブから1レース目を入れてください。」と案内する。

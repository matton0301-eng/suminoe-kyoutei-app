# スミノエ・リード — 住之江 出走表アナライザ

公式番組表を取得して、住之江の全12レースの判断材料を1枚のMarkdownにまとめる CLI ツール。
レースが終わったあとは、**事前の読みと実際の結果を照合**できる（`review.py`）。

> **このツールは勝つための予想ツールではありません。**
> 舟券の控除率は約25%あり、データ分析でそれを覆すことは想定していません。
> 目的は「根拠を持ってレースを見られること」です。買い目は定石の型の提示に留め、
> 母数の小さい数値には必ず母数を併記しています。

確定仕様: [../../docs/02-suminoe-read-spec.md](../../docs/02-suminoe-read-spec.md)
番組表フォーマット: [../../docs/03-bangumihyou-format.md](../../docs/03-bangumihyou-format.md)

## セットアップ（PowerShell 7 / Windows 11）

```powershell
cd tools\suminoe-read
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
```

実行だけなら `requirements.txt`（`requests` のみ）で足ります。
`requirements-dev.txt` は `pytest` を追加します。

### LZH の解凍について（7-Zip は不要）

番組表は LZH 形式で配布されていますが、**Windows 11 標準の `C:\Windows\System32\tar.exe`
（bsdtar / libarchive）が LZH を解凍できます**。追加のインストールは不要です。実機で確認済み。

解凍手段は次の順で自動的に試されます。

1. bsdtar（`C:\Windows\System32\tar.exe`） ← 通常はこれで成功
2. 7-Zip CLI（`7z.exe`。PATH または `C:\Program Files\7-Zip\`）
3. Python `lhafile` パッケージ
4. すべて失敗したら、手動解凍の手順を案内して終了

**全滅した場合の対処**:

```powershell
# A) 7-Zip を入れる（https://7-zip.opensource.jp/）
# B) lhafile を入れる
pip install lhafile
# C) 手動で解凍して txt を直接渡す
python main.py --local-file .\cache\B260809.TXT --date 2026-08-09
```

> Git Bash の `tar` は GNU tar で LZH に対応していません。本ツールは常に
> System32 の `tar.exe` をフルパスで呼びます。

## 使い方

```powershell
python main.py                                   # 当日分（md,csv,json を出力）
python main.py --date 2026-08-09
python main.py --date 2026-08-09 --format md,csv,json,chat
python main.py --date 2026-08-06 --dry-run       # 動作確認
python main.py --local-file .\cache\B260809.TXT --date 2026-08-09
python main.py --max-bets 4                      # 買い目の型の点数上限
python main.py --no-cache                        # キャッシュを使わず再取得
```

### 出力

| ファイル | 用途 |
|---|---|
| `output/suminoe_YYYYMMDD.md` | 人が読む用。先頭のサマリーだけで当日の方針が立つ |
| `output/suminoe_YYYYMMDD.csv` | 1行1艇（12R×6艇=72行）。UTF-8 BOM付きで Excel でそのまま開ける |
| `output/suminoe_YYYYMMDD.json` | **スミノエ・ログの「買い目」タブに貼り付ける用**。賭式別の買い目がアプリ側で出る |
| `--format chat` | 標準出力。Claude に貼って相談するための圧縮テキスト |

### スミノエ・ログとの連携

JSON をスマホに送り、[スミノエ・ログ](../../apps/suminoe-log/)の「買い目」タブに貼り付けると、
レースごとに3連単・3連複・2連単・ワイド・複勝など**賭式別の買い目**が表示されます。
アプリ側は当日の記録（コース別1着率の実測）で評価を補正します。

JSON に入れているのは出走表の評価値と本ツールの判定までで、買い目の組み立てはアプリ側で行います
（当日の実測を反映させるため）。

生データは `cache/` に保存され、再実行時は再取得しません（`--no-cache` で無効化）。

## 結果との照合（`review.py`）

レースが終わったあとに、事前の判定が実際どうだったかを記録する。

```powershell
python review.py                     # 当日分
python review.py --date 2026-08-07
python review.py --date 2026-08-06 --local-program tests\fixtures\B260806.TXT --local-result tests\fixtures\K260806.TXT
```

出力:

| ファイル | 用途 |
|---|---|
| `output/review_YYYYMMDD.md` | 判定ごとの結果、コース別1着率の実測、レースごとの着順・決まり手・払戻 |
| `apps/suminoe-log/public/results.json` | アプリの買い目タブに結果を並べるためのデータ |

**成績データ（K）は全レースが終わってから確定する。** 住之江のナイターなら21時頃
（8/6 は 20:53 JST）。レース前の成績ファイルは中身が空の300バイトで存在するため、
サイズを見て「まだ確定していない」と判断している。

### 何が分かるか

- 判定（勝負/標準/見送り）ごとに、1号艇が1着だったか・軸が1着だったか
- コース別1着率の当日実測と基準値の差
- **枠なり進入だったか**（本ツールの前提が成立したか）
- レースごとの着順・決まり手・波高・失格艇
- 全賭式の払戻金（アプリ側で「提示した型が当たったか」を突き合わせる）

> **1日ぶんの結果は統計的にごく小さな母数で、分析の実力を示しません。**
> 控除率が約25%ある以上、型どおり買い続けて増える想定でもありません。
> 実際 2026-08-06 のデータで全賭式を機械的に買うと投資を下回ることを、テストで固定しています。

## 分析ロジック

レースごとに4指標を出します。いずれも**3段階の定性評価＋根拠となる数値**をセットで表示します。

| 指標 | 内容 |
|---|---|
| イン信頼度 | 1号艇が逃げ切れそうか（級別・当地勝率・全国勝率・モーター2連対率） |
| 波乱リスク | 3・4号艇の攻めが利きそうか（1号艇との勝率比較） |
| モーター注目艇 | 当日出走全艇のモーター2連対率の中央値+15pt以上の艇 |
| 総合判定 | 勝負／標準／見送り |

住之江は枠なり進入がほぼ確定（1枠→1コース100.0%）のため、**枠番=進入コース**として扱います。

### しきい値の調整記録

仕様 §4-4 に従い、2026-08-06 の実データ12レースで試算して初期案から調整しました。

**調整前の分布**: 見送り 8 / 標準 3 / 勝負 1 — 見送りが2/3を占め、実用に耐えませんでした。

| # | 問題 | 実例 | 対応 |
|---|---|---|---|
| 1 | A1級・全国勝率7.43 の1号艇が「イン低」 | 10R 福島勇樹（当地4.62） | **番組表には当地の走数が載っていない**ため、当地勝率は母数不明。母数の小さい数値で断定しない設計思想に沿い、「A1級かつ全国勝率6.50以上」を「高」の代替ルートとして追加 |
| 2 | 当地勝率が基準超のB級1号艇が「低」 | 7R 神田達也（当地5.44） | 「低」の条件を緩め、当地5.00以上または全国5.50以上またはA級なら「中」に |
| 3 | 買い目の1着候補に1号艇が入らない | 7R/8R/10R/12R で `1着{3,2}` 等 | **住之江の1コース1着率56.2%を無視していた**。勝負・標準は必ず1号艇を軸に置く形に変更 |
| 4 | 相手候補に6号艇が上位で並ぶ | 勝率だけでソートしていた | 相手選びのスコアにコース別1着率を加算し、枠の有利不利を織り込み（係数は #7 で確定） |
| 5 | 2号艇に実力者がいるレースが「読みどころなし」扱い | 1R（2号艇 A1・当地7.29） | 波乱リスクは仕様上3・4号艇しか見ないため、**代替軸**の判定を追加。見送りレースでも1号艇より明確に上位の艇がいればその艇を軸にした型を提示 |
| 6 | 3連単フォーメーションの3着候補に2着候補が入っていない | 全レース | `1-{2,3}-{4,5,6}` では「2着2号艇→3着3号艇」を買えず不自然。3着候補を上位4艇にして 2×4−2=6点に |
| 7 | **スミノエ・ログと軸が食い違う** | 3R（リード=2号艇軸 / アプリ=1号艇軸） | 代替軸の判定が「勝率差1.00以上」で枠の不利を無視していた。**コース補正込みのスコアで1号艇を上回るか**に変更し、係数もアプリ側と統一（`COURSE_WEIGHT_FIRST = 14`）。8/6の全12レースで軸が一致することを確認し、アプリ側のテストで固定した |

**調整後の分布**: 見送り 6 / 標準 4 / 勝負 2。
8/6 は一般戦（1号艇の級別が B1×6・B2×2）のため見送りが多いのは実態に沿っています。
8/9 は優勝戦日でA級が増えるため、勝負・標準側に寄る見込みです。

しきい値は `suminoe/analyzer.py` の冒頭に定数として集約してあります。

> **コース補正の係数（`COURSE_WEIGHT_FIRST` / `COURSE_WEIGHT_PLACE`）は
> `apps/suminoe-log/lib/betting.ts` と同じ値でなければなりません。**
> ずれると同じデータから2つのツールが違う軸を出します。
> アプリ側のテスト（`lib/raceCard.test.ts` の「リードが示した軸と、アプリが選ぶ軸が一致する」）が
> この不一致を検出します。
